# V4.29 Change Impact

- Scope: final order-dispatch authority for risk, position, market data and causal TTL across current and legacy Testnet paths, plus reviewer-side external file access for GitHub governance signing, CI milestone identity, compliance matrix, and workflow contract validation.
- Modified code: `src/trading_platform/v311/dispatch_guard.py`, `v36/user_execution.py`, `v379/execution_parity.py`, `v380/order_adapter.py`, `v384/testnet_execution_activation.py`, `v385/controlled_testnet_submit.py`, and the V4.29 validation contract.
- New authority/helpers: `trading_platform.v429.external_file_safety` and `trading_platform.v429.workflow_contract`.
- Final dispatch now rejects missing risk/position/market/causal authorities and expired RiskDecision, intent, or request deadline before gateway invocation. V3.85 shares the same M1–M5 checks; older direct-submit adapters fail closed; V3.36 accepts only a guarded dispatcher.
- Champion promotion now requires durable PASS records for every required gate, binds the authorization to the exact gate runs and fingerprints, and revalidates them at registry promotion and LIVE activation. A changed or invalidated gate blocks reuse.
- V3.75 live/shadow inference now requires a durable artifact compatibility grant and rechecks the current seven-dimension report, version/hash binding and dependency invalidations before each prediction call. The V4.29 preflight and CI workflow include M14.
- A bounded Ed25519-verified JSON linear-model loader checks artifact bytes, model/input/output schemas, feature/target versions, runtime/dependency/config compatibility and prediction constraints before returning a callable prediction model. The V3.75 runner binds that model ID/hash to the M14 grant; M15 is included in preflight and CI.
- Decision-trace parity now validates schema version, non-empty immutable records, unique ordered event offsets and the canonical content hash before returning PASS; comparisons preserve duplicate offsets so repeated events cannot disappear behind dictionary keying.
- M9's research boundary now inspects Python `__slots__`, mangled credential attribute names, and NumPy object arrays; direct `TuningDataView` construction applies the boundary before storing research rows.
- The M9 credential vault now requires an explicit persistent backend for production, supports Windows Credential Manager, stores no secret material in its audit ledger, and restores/revalidates metadata after restart. Dedicated service identity and process-isolation evidence remain open.
- M10 now serializes access to each SQLite EventStore connection across threads and adds concurrent hash-chain coverage; M9 resolution/revocation share a lock and record every access attempt. Independent storage tamper review remains open.
- M11 now requires a disk-backed side-effect journal before final transport, reuses a persistent dispatch-attempt/order-request/accounting EventStore when available, and blocks runtime dispatch when no persistent ledger is configured. External venue exactly-once behavior remains unverified.
- The source-checkout §178 launcher now disables bytecode generation before importing the platform. A subprocess regression removes `PYTHONDONTWRITEBYTECODE`, runs from an isolated source checkout, and verifies it leaves no `__pycache__` directories that would fail release hygiene.
- The uncertainty assessment ID now hashes canonical JSON outside the f-string expression, preserving the same identity while parsing on the declared Python 3.10+ minimum. A regression parses every `src/` and `scripts/` Python file with Python 3.10 grammar so newer syntax cannot silently break the supported runtime or CI.
- M24 retains model-health source identity, capture time, TTL, verification state and assessment time; authority/capability fingerprints and durable risk decisions bind the exact source. Runtime commit and durable revalidation reject changed or expired evidence; signed source identity and live source integration remain open.
- M23 derives drawdown from hash-chained accounting snapshots anchored by an explicit opening-history evidence ID. Runtime authority, order routing, one-shot capabilities and durable risk decisions bind the same drawdown assessment and its freshness. The bootstrap verification flag is an assertion, not an independently authenticated history attestation.
- M18 invalidation now computes transitive closure through evidence source/dependency references, gates, candidates and promotions in addition to artifact graph nodes. The durable record enumerates exact revalidation targets; production-wide registry completeness and independent review remain open.
- M22 now derives liquidity stress from synchronized order-book depth utilization, quoted spread and estimated order VWAP impact. The exact snapshot, source record, order and configured limits are fingerprinted through runtime authority, routing, capabilities, durable decisions and final dispatch; real-feed authentication and independent threshold calibration remain open.
- M21 now requires a separate calibration report to lift the conservative `UNKNOWN` cap; a signed manifest's calibration state alone is metadata. The assessment fingerprint binds report sources, sample sizes, metrics, drift and state through runtime authority, router, one-shot capability, durable risk decision and final dispatch. The fingerprint does not authenticate report producer or dataset; real-data calibration and multiplier ablation remain open.
- The complete offline §178 acceptance runner is exposed from a checkout through `python scripts/run_offline_acceptance.py`, and after installation through `python -B -m trading_platform offline-acceptance`. It emits its deterministic JSON report and has a test that fails on socket connection attempts; it does not enable exchange or production access.
- A separate explicit market-data command downloads only Binance USD-M Futures daily archive ZIPs and checksum sidecars from the exact public-data host. It disables proxies and redirects, bounds all requests/archives, validates archive paths and rows, records immutable raw and normalized data, and requires a non-commercial research attestation because the current source terms exclude live proprietary/commercial trading.
- M25's application policy now requires exact allowlisted hosts on the default TLS port and denies URL userinfo and malformed ports. Research remains deny-all, and the public-data zone cannot reach Testnet or Production exchange hosts; application policy does not prove infrastructure routing.
- License-restricted archives are written only to a new non-overwriting snapshot outside the repository checkout. The manifest retains source attribution/license scope and the normalized content hash.
- DATASET-01 has a bounded local-only CSV audit and paired-source comparison command. It creates separate DatasetContracts when coverage is complete, joins on normalized UTC event time and symbol, records unmatched keys and field-level OHLCV deltas with bounded tolerances, and documents operator notes for each source. It does not prove source independence or assess licensing/authority. No user CSV is present, so no actual dataset comparison is claimed.
- Safety properties: no-follow descriptor traversal, bounded regular-file reads, consistency checks during read, no-overwrite output creation, `0600` output permissions, and fail-closed behavior on unsupported platforms.
- Operational effect: the Testnet submit API now requires current durable authority evidence through the controlled path. Tests use fake gateways; no Testnet order, Production mutation or deployment activation is performed.
- M24 verification covers source fingerprint changes, restart persistence, tamper detection, and source expiry at commit and durable authorization. Synthetic evidence does not establish independent authenticity or operational source wiring.
- M23 verification covers bootstrap requirements, replayed historical peaks, monotone/fresh snapshots, accounting-truth binding, source changes, capability expiry and durable risk-cap enforcement. The suite uses synthetic snapshots; no real portfolio or authenticated accounting history was provided.
- M14 and M15 remain `TESTED`: the signed model format and grant binding have local coverage, but production inference integration, an independently governed trust root, reviewer verification and deployment evidence remain open.
- Reversibility: revert V4.29-specific runner, workflow and signer/helper changes; retain the V4.28 recovery archive as the direct baseline.
